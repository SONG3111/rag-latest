# 02 端到端流程

本文按"用户做了什么 → 系统内部发生了什么"的顺序，把四条主链路拆开讲清楚。
每一节末尾都标注了**代码位置**和**常见失败点**。

## 流程 A：上传文件到可检索

**用户动作**：在工作区里选择 `销售表.xlsx` 上传。

```
浏览器                    后端                          磁盘 / 存储
  │  POST /files           │
  ├───────────────────────▶│ ① 校验：后缀 .xlsx/.xlsm/.docx，大小 ≤ 200MB
  │                        │ ② 文件名净化（去掉路径分隔符与控制字符）
  │                        │ ③ 同名冲突 → 加 "(1)" 后缀
  │                        ├──────────────────────────▶ data/workspaces/<ws>/销售表.xlsx
  │                        │ ④ 写一条 document_files（status=pending）
  │                        │ ⑤ 解析 + 父子分块
  │                        │      Excel: 表头 → 每行一个子块，12 行一个父块
  │                        │      Word : 按标题分章节 → 父块=章节，子块=段落/表格行
  │                        │ ⑥ 子块写入 chunks + 计算 BM25 词频
  │                        │ ⑦ 子块向量化（本地 bge-m3，1024 维）→ Qdrant
  │                        │ ⑧ 更新 status=indexed, chunk_count, indexed_at
  │  201 + 每文件索引结果   │
  │◀───────────────────────┤
```

要点：

- **父块不入向量库**。它只存在 SQLite，用来在命中子块后补充上下文，这让嵌入量少一半。
- **上传即索引**（同步执行）。文件大时这一步会比较久，期间请求一直挂着。
- 索引失败不会让整个上传失败：文件仍写入磁盘，`document_files.error` 记录原因，
  界面上显示错误标记，用户可以点"重新索引"。

**代码位置**：`backend/app/api/routes.py`（`upload_files`）、
`backend/app/services/files.py`（`save_upload` / `index_file`）、
`backend/app/retrieval/chunking.py`。

**常见失败点**：
| 现象 | 原因 |
|---|---|
| `no such column: chunks.level` | 老数据库缺列，`migrations.py` 没跑（重启后端即可） |
| 上传成功但检索不到 | 嵌入维度与 `EMBEDDING_DIMENSIONS` 不一致 |
| 表格内容被截断 | 单行长文本按 1200 字上限切分（`MAX_CHILD_CHARS`） |

## 流程 B：知识库问答（一次完整检索）

**用户动作**：问"制度里规定的招待费上限是多少？"

```
① 路由：加载最近 60 条消息作为历史 + 时效性检查
        │   文件在上一条消息之后变过 → 额外注入一条系统提示
        ▼
② Agent 第 1 次模型调用（流式）
        │   模型决定：调 search_knowledge_base({query: "招待费上限"})
        ▼
③ tools 节点执行检索（本地工具，直接执行）
        │
        ├─ 3.1 查询改写（LLM，glm-5.2）：结合历史把问题补全
        │       失败/超时 → 回退原查询（不阻断检索）
        ├─ 3.2 双路召回：向量 top20 / BM25 top20（都作用于子块）
        ├─ 3.3 去重：同一片段两路都召回时按内容指纹合并
        ├─ 3.4 RRF 融合：score += weight / (60 + rank)
        ├─ 3.5 重排：本地交叉编码器给 20 个候选打真实相关性分
        ├─ 3.6 阈值过滤：低于 0.02 的丢弃（全被丢弃 → 返回空）
        └─ 3.7 组装：命中子块的父块文本 + 精确位置 + 分数
        ▼
④ 工具结果回填给模型（JSON：results[] + retrieval 元信息）
        ▼
⑤ Agent 第 2 次模型调用：基于结果生成回答 + 标注 [文件 · 位置]
        ▼
⑥ 路由：把 token / citations 事件推给前端，并把最终文本与引用落库
```

前端的 SSE 事件序列（实测样例）：

```
tool_call    {tool: "search_knowledge_base", label: "正在检索知识库：招待费上限"}
tool_result  {ok: true, data: {results: [...]}}
citations    {items: [{file: "制度.docx", location: "段落 2", score: 0.982}]}
token        "制度规定，**招待费单笔不得超过 3000 元**"
token        "。[制度.docx · 段落 2]"
done         {content: "制度规定，**招待费单笔不得超过 3000 元**。[制度.docx · 段落 2]"}
```

要点：

- **拒答是合法结果**。全部候选低于阈值时工具返回空结果 + 一句提示，
  系统提示要求模型如实说"没有找到"，而不是用常识补答。
- **引用来自工具结果，不是模型编的**。前端引用面板与回答里的标记都指向同一批
  `file + location`。
- **改写失败不影响检索**：没有 key、超时、输出超长都会静默回退原查询。

**代码位置**：`backend/app/agent/graph.py`（`_knowledge_tool`）、
`backend/app/retrieval/pipeline.py`（`Retriever.search`）、
`backend/app/retrieval/rewriter.py`。

## 流程 C：对话式改文件（审批闭环）

**用户动作**：说"把销售表里 A型 的销售额改成 1111"。

```
① Agent 第 1 次调用 → read_range（读取确认位置）
② Agent 第 2 次调用 → update_cells（写入意图）
        │
        ▼
③ tools 节点识别：这是 MCP 工具，且没有 readOnlyHint → 不执行！
        │
        ├─ 3.1 补齐参数：读取目标单元格当前值（用于 Diff 与 digest）
        ├─ 3.2 生成 Diff：[{cell: "C2", before: 1000, after: 1111}]
        └─ 3.3 落库 operations（status=proposed，含备份路径占位）
        ▼
④ 模型收到：{status: "pending_user_approval", summary: "..."}
        │   于是它在回复里说"已提交提案，请在右侧确认"
        ▼
⑤ 前端展示 Diff 卡片（逐项可勾选），用户点"应用修改"
        │
        ▼
⑥ POST /operations/{id}/apply
        ├─ 6.1 备份原文件 → data/backups/<ws>/销售表.xlsx.<时间戳>
        ├─ 6.2 真正调用 MCP 工具写盘
        ├─ 6.3 status=applied，记录结果
        └─ 6.4 重建该文件的索引（内容变了，分块必须刷新）
        ▼
⑦ 界面显示结果；另一个入口是"还原"（restore 备份）
```

### 状态机

```
        ┌──────────┐  用户确认   ┌─────────┐  用户点还原  ┌──────────┐
        │ proposed │───────────▶│ applied │────────────▶│ rejected │
        └────┬─────┘            └─────────┘  (恢复备份)   └──────────┘
             │ 用户拒绝
             └──────────────▶ rejected
             │ 执行失败（文件被删、工具报错）
             └──────────────▶ failed
```

（还原后状态记为 `rejected` 并带说明 `reverted to the pre-change backup`，
因为从审计角度看这次写入"没有生效"。）

要点：

- **提案不落盘**。测试里有一条断言：拒绝后原文件字节级不变
  （`backend/tests/test_operations.py`）。
- **重复确认会被拒**：只有 `proposed` 状态才能 apply。
- **备份保留最近 50 份**（`prune_backups`），不会无限增长。
- **写后重建索引**：否则检索还会返回旧数据——这也是"时效性"问题的一个来源。

**代码位置**：`backend/app/agent/graph.py`（门控与 `_propose`）、
`backend/app/services/operations.py`、`backend/app/services/backup.py`。

## 流程 D：追问、时效性与兜底

这是踩坑最多的一条链路，单独讲。

### D1 正常追问

用户先问"报销制度规定了什么"，再问"那第三条呢"：

- 历史（最近 60 条）带上第一轮的问答；
- 改写器看到历史，把"那第三条呢"补成"员工费用报销管理制度第三条规定了什么"；
- 检索命中第三条款所在章节，回答带出处。

### D2 文件变了之后

用户重新上传了表格（或用 Excel 直接改了文件），此时**上下文里的旧答案已经不可信**：

```
每轮开头：
  cutoff = 最近一条消息的时间
  changed = [{文件, 变更时间} for 文件 in 工作区 if max(indexed_at, mtime, created_at) > cutoff]
        │
        ├─ changed 为空 → 什么都不做（正常对话，允许复用上一轮结论）
        └─ changed 非空
               ├─ 注入系统提示："这些文件变了，旧结论作废，必须重新读取"
               └─ 若模型仍然没调用任何工具就给出带数值的文档结论
                      → nudge：把这段草稿从上下文移除，要求它先读文件再回答
```

### D3 模型没输出正文

推理模型偶尔"在脑子里回答"：只输出 `reasoning_content`，`content` 为空。
LangChain 不暴露 reasoning，于是这一轮看起来是空的。处理：

```
模型返回 → 有 tool_calls？ → 执行工具
         → 没有 tool_calls 且正文为空？ → nudge（空回复纠正），最多一次
         → 第二次仍为空 → 落库一句"模型这次没有返回内容，请再说一次。"
```

这两类兜底共用同一个计数器，**每轮最多纠正一次**，避免"模型不改 → 系统打回 →
模型不改"的死循环。

### D4 一个真实的时间线（实测）

```
14:18:37  用户重新上传 销售表(1).xlsx      → indexed_at 更新
14:19:00  问"表格内容？"
          ├─ 检测到文件在上一条消息(14:15:25)之后变过 → 注入提示
          ├─ 模型调用 list_files → get_doc_structure → read_range
          └─ 回答：A型 华东 1000 / B型 华北 2500 / C型 华南 3000   ✅ 正确
14:19:22  问"你调用工具后再回答我"
          └─ 文件未再变化 → 允许直接回答
```

对照修复前的行为：模型不调工具，直接复述上一轮的旧数字，并且因为历史窗口取的是
对话开头，它连"刚刚读过新数据"这件事都看不到。

## 流程 E：删除与重建

| 操作 | 接口 | 做了什么 |
|---|---|---|
| 删除文件 | `DELETE /files/{fid}` | 从向量库删除该文件的分块 → 删磁盘文件 → 删数据库记录 |
| 重建单文件 | `POST /files/{fid}/reindex` | 重新解析分块、重新嵌入（换分块策略后用） |
| 重建工作区 | `POST /reindex` | 全工作区重建（换嵌入模型/维度后用） |
| 删除工作区 | `DELETE /workspaces/{id}` | 级联删文件、分块、消息、操作记录 |

索引是**派生数据**：删除时即使向量库报错也不会阻塞删除流程（只记 warning），
因为磁盘文件与数据库才是事实来源。

## 附：失败路径手册

| 症状 | 真实原因 | 处理 |
|---|---|---|
| 前端 502 / Connection error | Windows 系统代理被 httpx 读到 | 所有 HTTP 客户端显式 `trust_env=False`（`llm/providers.py`） |
| 页面全白 | `a-empty` 收到 `:image="null"` 抛 TypeError | 自己写空状态，不用该 prop |
| 回复要切走再切回才显示 | 流式回调改了推送前的局部对象，不是响应式代理 | 用 `turnById()` 按 id 查找后再改 |
| 工具调用/提案事件丢失，文本最后一次性出现 | SSE 帧是 CRLF，前端按 `\n\n` 切分永远匹配不上 | 按行解析（`composables/sse.ts`） |
| 长对话答非所问 | 历史取了最早 60 条 | `_recent_messages()` 取最近 60 条 |
| 表格只有表头 | `read_range` 不传 `end_cell` 时只返回一个单元格 | 已对齐上游语义：自动扩展到数据末端 |
| `no such column` | `create_all` 不改已有表 | 启动时跑 `migrations.py`（只增不删） |
| 检索结果明显变差但不报错 | 向量库被另一个进程占用 → 自动降级成纯 BM25（只记 warning） | 确认没有第二个进程在访问 `data/qdrant`；需要并行就换 Qdrant server |
| 回答是"模型这次没有返回内容" | 推理模型只输出了思考、没给正文 | 系统已自动重问一次；仍为空才会显示这句 |

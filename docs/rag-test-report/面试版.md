## 0. 三十秒版本（面试官的第一问）

> 形态的办公文档 + 专门设计来'逼切块器下刀'的对抗文档。全程 BM25 离线测评、
> 零模型调用。结论分两层：参数层面，512/64/12 就是最优档，不用改；策略层面，
> 我对照 LangChain/Tony Baloney 的 CJK 最佳实践，给切分器补上了中文逗号
> 分隔符——在一篇'没有句号、只有逗号'的对抗长文上，句子被拦腰硬切的比例
> 从 100% 降到 0%，而召回率和块数完全不变。过程中还抓出我们切断率指标的
> 一个 bug（把表格行误当成切分边界），修正后所有参数档的真实硬切率其实是
> 0——这个'评测自己的评测'的过程，是我最有底气的部分。"

## 1. 问题定义

RAG 分块（chunking）决定检索单元的粒度。三个待测参数：

| 参数 | 含义 | 当时的值与出处 |
| --- | --- | --- |
| `chunk_size_tokens` | 单个子块（被索引、被检索的单元）的最大长度 | 512，bge-m3 官方建议 |
| `chunk_overlap_tokens` | 相邻子块共享的重叠长度 | 64，约 12%，bge-m3 官方建议 |
| `rows_per_parent` | Excel 多少行组成一个父块（上下文单元） | 12，经验值 |

策略本身（结构感知 + 父子双层：子块负责被搜到、父块负责给模型看全上下文，
parents 不参与 embedding）也要验证：它相对"整篇定宽切"到底值不值。

**核心问题：这些数字和这套策略，在我的任务上是最优的吗？**

## 2. 测评集构成（重点）

三个子语料，对应三种考察目的，共 35 个文件、238 道标注题：

### 2.1 CMRC 2018 权威公开集（210 题）

- **来源**：[ymcui/cmrc2018](https://github.com/ymcui/cmrc2018)，哈工大&
  讯飞合办的中文抽取式阅读理解数据集（EMNLP 2019 论文），GitHub 直接下载
  dev 集 3.3MB，许可 CC BY-SA 4.0（署名+相同方式共享，评测使用合规）。
- **用法**：数据每条是「一篇短文 + 若干问题 + 答案原文片段（span）」。
  我们把文章变成 Word 章节，问题当查询，答案片段当判分依据。
- **两种难度**：
  - **标准集**：240 篇文章 → 16 个 docx（每篇一个章节），150 题。
    每篇文章约 450 字，考查"段落级分块 + 检索"的基本盘；
  - **压力集**：60 篇文章**五篇拼成一个约 2300 字的超长段落** → 12 个
    docx，60 题。强迫切分器真的下刀，专门暴露切块边界和重叠参数的问题。
- **为什么选它**：中文、公开、权威（论文级基准）、答案可机器判分（不用
  LLM 当裁判）、规模够做参数排序。

> 为什么不用 CRUD-RAG 当语料？[CRUD-RAG](https://github.com/IAAR-Shanghai/CRUD_RAG)
> （IAAR-Shanghai，arXiv 2401.17043，Apache-2.0）是中文 RAG 最权威的基准
> 之一，论文里专门扫过 64/128/256/512 四档块大小。但它的检索库是 **8 万条
> 新闻文档**（需要构建 milvus 向量索引），评测指标（RAGQuestEval）**用 GPT
> 当裁判**——两条都和"离线、零模型调用、可复现"的测评纪律冲突。所以它的
> **结论**被我们引用（见第 7 节），语料不搬。

### 2.2 业务仿真集（28 题）

- 项目自带的「报销制度 docx + 报销明细 xlsx」（8 行小表）+ 一张新建的
  60 行大表，覆盖：政策条款问答、表格行级问答（"张伟报销了多少"）、
  聚合问（"技术部有哪些记录"）、口语问法（"报销咋整"）。
- **为什么必须有**：CMRC 全是纯文本短文，测不到 Excel 行分块、表头绑定、
  父块行数这些我们真实依赖的能力。

### 2.3 对抗结构集（不计检索分，计结构分）

| 文件 | 考察点 |
| --- | --- |
| 堆叠表 xlsx（空行分隔双表头） | 第二张表能否挣脱第一张表的表头 |
| 26 列宽表 xlsx | 超宽行是否超 token 预算 |
| 超长段落 docx（2400/4800 字） | 常规长文切分是否落在句号上 |
| **无句号长句 docx（第二轮新增，约 2000 字只有逗号）** | **分隔符分层是否生效：没有句号可切时，切在逗号边界还是词组中间** |

它们只测**结构合规**（块超预算率、硬切率/糙边率），不进检索排名——它们
的存在会让 BM25 的词频统计失真。第二轮修正了"对抗文件只切块不计量"的
实现，让上面的考察点真正有数字（第一轮它们被切块后丢弃了，docstring 却
声称已计量——这也是本轮抓出来的问题之一）。

**一句话总结设计逻辑：公开权威集保公信力，业务集保贴合度，对抗集保下限，
三者互补且全部可离线复现。**

## 3. 测试方法（重点）

### 3.1 隔离变量：只让"切块"动

检索管线里查询改写、向量召回、BM25、重排、相关性闸门五个环节都会影响
结果。这次**只开 BM25、关掉其余**（`use_dense=False, use_rerank=False,
use_rewrite=False`），每次只换切块参数重建索引。这样 recall 的任何变化
都只能来自切块。

> BM25 是纯本地计算（jieba 分词 + 内置打分），全程**零模型调用**，符合
> 项目"测试不烧 token"的纪律。长度计量用本地 bge-m3 tokenizer 的真实
> token 数——块"多大"以 embedding 模型看到的为准。

### 3.2 指标定义（口语版）

| 指标 | 通俗含义 | 为什么看它 |
| --- | --- | --- |
| **Recall@5** | 238 题里，前 5 个检索结果中"包含标准答案的父块"的占比 | 主指标：模型读到的上下文对不对 |
| **MRR@5** | 正确结果排得越靠前分越高（第 1 名=1.0，第 5 名=0.2） | 排序质量，影响上下文窗口利用率 |
| **child_precision@5** | 命中的**子块本身**（而非父块）包含答案的占比 | 引用粒度：能不能把用户点到精确的那一行/那一段 |
| **硬切率** | 分块边界处，上一块**任何标点都没有**就断掉（词组中间被剁开）的比例 | 最伤质量的一档：embedding 语义断裂、引用不可读 |
| **糙边率** | 上一块停在逗号/顿号（子句边界）而非句号的比例 | 可接受但次优：语义完整、只是不是最佳停顿 |
| **子块数** | 全语料切出的索引单元总量 | 成本代理：embedding 计算和存储与之成正比 |

> **硬切率和糙边率是第二轮拆开的两档**。第一轮只有一个"拦腰切断率"，
> 而且有个 bug：Word 表格行没有切分片号（part），被默认值顶成了"第 0 片"，
> 于是表格行与行之间被误判成切分边界——4 张表格行贡献了全部"13% 切断率"。
> 修正后只统计**真正的多片切分**（上一片带 part 号、下一片连续），并新增
> 无句号长句文档让这两档指标有真实的分母。这个 bug 的教训进第 8 节追问。

### 3.3 参数网格与流程

```
块大小 ∈ {256, 384, 512, 768} × 重叠 ∈ {0, 32, 64, 128}  → 16 组
每组：重建全语料索引（真实切块函数 + bge-m3 tokenizer 按实测 token 计量）
     → BM25 检索 → 指纹去重 → 取 top5 → 按子语料分别判分
再固定最优 (size, overlap)，扫 rows_per_parent ∈ {6, 12, 24}
```

另加两个策略对照实验（见第 5 节）：朴素定宽切分、分隔符分层（legacy vs
中文子句感知，在 512/64 与 768/64 双档对拍）。

### 3.4 可信度保障（评测的评测）

1. **等价性校验**：快速评测路径 vs 项目真实 `Retriever` 管线（含
   `index_file` 入库），同样 12 题对拍 top5——**0 不一致**。这一步还揪出
   一个真实 API 陷阱：`BodySplitter` 的切块预算由调用参数决定，注入自定义
   切分器而不传预算参数时会被默认值 512 静默覆盖（已加回归测试钉死）；
2. **确定性**：语料抽样用 SHA-256 键排序而非随机数，任何机器重跑得到
   同一份 238 题卷子；
3. **子语料隔离**：三个子语料各建各的 BM25 索引分——混在一起时，60 行
   大表会用自己的重复词项把 8 行小表的正确行挤出 top5（实验中实测到的
   竞争伪影），分库打分才反映真实工作区行为；
4. **成本指标与质量指标分母分离**：子块数/尺寸只统计可入库语料（对抗
   文件不是真实索引对象），边界质量统计覆盖全部文件（对抗文件存在的意义
   就是让切分器下刀）。

## 4. 核心数据

### 4.1 网格扫描（16 组，生产分隔符，硬切率全部为 0%）

| 块大小 | Recall@5 | MRR@5 | 子块数 | 硬切率 | 糙边率 |
| --- | --- | --- | --- | --- | --- |
| 256 | 97.48% | 0.9625~0.9678 | 830（overlap=64 档） | 0% | 8~15% |
| 384 | 97.48% | 0.9566~0.9636 | 544 | 0% | 7~8% |
| **512（现行）** | **97.48%（overlap=0 时 97.90%）** | 0.9636~0.9654 | **450** | **0%** | **2~3%** |
| 768 | 97.90% | 0.9644~0.9672 | 373 | 0% | 3~6% |

- **召回**：512 与 768 只差 1 题（97.48% vs 97.90%，238 题的 0.42 个
  百分点，噪声级）；重叠 0/32/64/128 差异同样 ≤1 题。
- **硬切率全线 0%**：正常中文文本句号密度足够，切分器总能在句号上收刀——
  "块越大切得越碎"的担心在这个语料上**不成立**（这正是第一轮指标 bug
  掩盖的事实）。
- **糙边率**来自无句号长句对抗文档落在逗号上的收刀，属预期行为。

### 4.2 rows_per_parent（Excel 每父块行数）

6/12/24 三档召回完全一致（小表 0.90、大表 1.00）。这个参数不影响"搜不
搜得到"，影响"搜到后模型看到的表格上下文全不全、引用粒度细不细"。12 行
≈ 一屏表格，是上下文完整性与引用精确度的平衡点。

### 4.3 失败用例归因（512/64 基线，共 6 例失败）

| 失败类型 | 数量 | 归因 |
| --- | --- | --- |
| 口语化业务问（"报销咋整""谁还没给批啊"等） | 5 | BM25 单腿的已知短板，线上由查询改写+向量检索补齐——**与切块无关**（所有参数组合下同样失败，这本身就是"锅不在切块"的证据） |
| CMRC 压力集 1 例（"钟惺有哪些代表作"，答案跨切断边界） | 1 | overlap=0 的组合能对——重叠的重复内容偶发挤占 top5 名额，1 题量级，噪声范围 |

### 4.4 统计诚实性

238 题里 1 题 = 0.42 个百分点。所有 ±1 题的差异（重叠各档、512 vs 768）
都**不构成统计显著**。真正的决策依据是结构性与成本性指标：256 的 +71%
子块、768 的引用粒度变粗（见 6 节），都不依赖统计显著性。

## 5. 策略对照实验

### 5.1 朴素定宽切分 vs 结构感知父子分块

朴素 = 整篇文档拼成大文本，按固定宽度递归切，无结构、无父子、无表头
（LangChain `RecursiveCharacterTextSplitter` 的默认用法，网上教程标配）。

| 维度 | 朴素定宽 | 结构感知（本项目） |
| --- | --- | --- |
| CMRC Recall@5 | 99.5% | 99.5% |
| 引用定位 | 只能说"第 42 块" | "报销明细!第 5 行"、"段落 8（第二章 报销限额）" |
| Excel 表头绑定 | 行内是裸值 `BX-2026-001 \| 张伟 \| 3200` | 自描述 `姓名=张伟, 金额=3200` |
| 公式列 | 丢（openpyxl 读不到缓存值即丢列） | 公式文本兜底，列不消失 |
| 父块上下文 | 无 | 检索命中自动带出整节/整块表格 |

**结论：召回打平，但引用体验、数据自解释性、鲁棒性三项结构性胜出——
保留现有策略。** 面试要点：纯召回不是分块策略的胜负手，"检索到之后模型
能不能用好"才是。

### 5.2 分隔符分层（第二轮采纳上线）

**背景**：切分器按优先级依次尝试分隔符。第一轮的分隔符列表是
`["\n\n", "\n", "。", "！", "？", "；", "!", "?", ";", " ", ""]`——
**中文里没有词间空格**，一个没有句号的长句会一路穿透到末尾的 `""`
（逐字硬切）。第一轮其实试过加"，"，但把它插在了空格**后面**，而且
语料里恰好没有触发场景，测出"零差异"后按"无数据不改代码"放弃了——
**那个实验本身是无效设计**：排序错了永远不会被触发的东西。

**调研依据（GitHub 迁移，MIT/博客思路，非逐行复制）**：

- [Tony Baloney《CJK best practices》](https://tonybaloney.github.io/posts/cjk-chinese-japanese-korean-llm-ai-best-practices.html)：
  中文/日文必须用全角标点做分隔符，并按"句号 → 感叹/问号 → 逗号/顿号"
  的层级排序（其参照 W3C 日文排版需求标准）；
- LangChain 官方文档 CJK 章节：默认分隔符 `["\n\n", "\n", " ", ""]` 对
  中日泰等无词边界语言次优，建议自定义；
- RAGFlow（infiniflow/ragflow）的通用切分同样把中文句读作为一级分隔符。

**改动**：`BODY_SEPARATORS` 变为
`["\n\n", "\n", "。", "！", "？", "；", "!", "?", ";", "，", "、", ",", " ", ""]`
——句号层级不变，**子句层级（，、,）插在空格和硬切之前**。

**测量**（新增对抗文档"无句号长句"：约 2000 字、只有逗号没有句号）：

| 变体 | 无句号长句硬切率 | 切分边界数 | 全语料硬切率 | CMRC 压力集召回 | 子块数 |
| --- | --- | --- | --- | --- | --- |
| legacy（无子句层）@512/64 | **100%**（10/10 片都断在词组中间） | 10 | 8.5% | 98.3% | 450 |
| **clause-aware（上线）@512/64** | **0%**（全部收在逗号边界） | 3 | **0%** | 98.3% | 450 |
| legacy @768/64 | 83% | 6 | 14.3% | 100% | 373 |
| clause-aware @768/64 | **0%** | 2 | **0%** | 100% | 373 |

**解读**：召回、子块数**逐位不变**——这个优化不碰检索，纯粹把"必然发生
的切分"从词组中间挪到子句边界，embedding 拿到的不再是断头语义，用户点
引用看到的不再是半句话。同时边界数从 10 降到 3：子句级合并让每片更大更
完整。**零成本、纯收益，且行为被 2 个回归测试钉死**（分隔符排序 pin +
无句号长句功能测试）。

## 6. 决策与落地

| 项 | 决定 | 落地 |
| --- | --- | --- |
| 512 / 64 / 12 | **保留**（从"抄的"变"测的"） | 理由：768 只多对 1 题（噪声）却让每个子块变大 50%——child_precision 不降但父块上下文翻倍稀释，且超出 bge-m3 建议的检索单元窗口；256 子块 +71% 成本。CRUD-RAG 论文结论"问答类任务最优块大小在中小档"与我们一致，而它"大块利于结构"的收益已由父层免费提供 |
| 分隔符分层（，、,） | **采纳上线** | `chunking.py` + 出处注释 + 2 个回归测试；对抗测量见 5.2 |
| 切分边界指标 bug | 修正 + 教训沉淀 | 只统计真正的多片切分；修正后所有档位硬切率 0% |
| 对抗文件计量缺失 | 修正 | 对抗文件进结构统计、不进检索索引 |
| BodySplitter 预算契约 | 文档化 + 测试钉死 | `chunking.py` docstring；`test_injected_splitter_size_is_overridden_by_budget_argument` |
| 换朴素切法 | 否 | 召回打平但丢引用/表头/公式三件套 |
| 评测资产 | 沉淀为脚本 | `scripts/eval_chunking.py`（任何人可复现，等价性校验内置） |

落地验证：backend 全量测试套件 **179 用例全部通过**（全 mock，零真实模型调用）。

## 7. 与业界方法的关系（研究调研）

测评集选型与优化方向均先调研 GitHub 主流实现，按"当前约束下能否落地"分层：

| 方法 | 代表来源 | 一句话原理 | 我们的结论 |
| --- | --- | --- | --- |
| 递归结构切分 + 父子检索（small-to-big） | LangChain `ParentDocumentRetriever`、LlamaIndex `AutoMergingRetriever` | 小块检索、大块喂模型 | **已实现**，两轮验证有效 |
| CJK 分隔符分层 | Tony Baloney CJK 指南、LangChain CJK 文档、RAGFlow | 中文按句读标点分层下刀，子句层先于硬切 | **本轮迁移上线**，对抗测量硬切 100%→0% |
| 中文权威基准 | CMRC 2018（EMNLP 2019）、[CRUD-RAG](https://github.com/IAAR-Shanghai/CRUD_RAG)（arXiv 2401.17043，Apache-2.0）、DuReader（百度，Apache-2.0） | — | **CMRC 已用**；CRUD-RAG 结论已引用（块大小无万能最优、按任务定档），其 8 万条新闻库 + GPT 裁判与离线纪律冲突，语料不搬；DuReader 长文档列入下一轮扩语料 |
| 语义分块 | LlamaIndex `SemanticSplitterNodeParser` | 按 embedding 相似度在"话题转折处"下刀 | 需要 embedding 逐句算；学术评测（arXiv 2410.13070）显示收益不稳定、成本高——暂缓 |
| 上下文检索 | Anthropic 官方工程博客 + Cookbook | LLM 给每块生成一句上下文摘要拼进块内，检索失败率降 30%+ | 每块一次 LLM 调用，与"测试不烧 token"纪律冲突——列入生产路线图 |
| 晚分块 | [jina-ai/late-chunking](https://github.com/jina-ai/late-chunking)（arXiv 2409.04701） | 整篇先过长上下文 embedding，再对 token 向量做池化切块 | 需要长上下文 embedding 模型（8K+），当前 bge-m3 工作流需改造——观察中 |

## 8. 追问预演

**Q：你说抓了一个指标 bug？讲讲。**
A：第一轮的"拦腰切断率"把 Word 表格行也当成了切分边界——表格行的元数据
里没有切分片号，代码用默认值 -1 顶上后，"片 0 跟在片 -1 后面"恒成立，
于是每两行表格之间都算一次"切断"。4 张表格行贡献了全部 13%。修正方法：
只有上一块**明确带片号**且下一块片号连续才算边界。教训是一句话——
**评测脚本也是代码，指标定义错了数据会一本正经地说谎**；所以第二轮我把
"对抗文件必须真的被计量""成本和质量指标分母分离"写进了方法的可信度
保障里，并且所有指标都能从原始 JSON 里逐条对回。

**Q：为什么不用 LLM 当裁判打分（RAGAS 那套）？**
A：两个原因。一是判分对象不同：RAGAS 评端到端生成质量（faithfulness、
answer relevance），本轮目标是隔离"切块"这一个变量，LLM 裁判会把生成端
的噪声混进来；二是成本与可复现：LLM 裁判每次跑结果都漂，span 判分是
确定性的，0 和 1 没有争议。端到端评测是下一轮，需要真实模型配额。

**Q：BM25-only 的结论能推广到向量检索吗？**
A：部分能。切块的产物（子块文本）同时喂给 BM25 和 embedding，"块超预算、
硬切率、表头绑定、分隔符分层"这些结构性结论与检索腿无关；召回排序的结论
对 BM25 成立，对向量腿属于强假设。所以报告里明确写了局限：稠密腿的验证
需要本地 bge-m3 权重跑 embedding，是下一步。

**Q：分隔符这个优化，为什么第一轮否了第二轮又采纳？**
A：因为第一轮的实验是无效设计，我承认这一点。第一轮把"，"插在空格后面
——中文没有空格，排在空格后面的分隔符永远轮不到；语料里又恰好没有无句号
长句，所以测出"零差异"。第二轮做对了两件事：先把顺序改对（逗号排在空格
和硬切之前，这是 Tony Baloney 和 LangChain 的 CJK 标准 做法），再造出
触发场景（无句号长句对抗文档）让差异可测。结果 100%→0% 硬切、召回逐位
不变。**"按无数据不改代码"没错，错的是把无效实验的数据当成了"没有数据"。**

**Q：为什么 512 和 768 只差 1 题还敢下结论？**
A：决策不押在显著性上。768 真实的问题在别处：每个子块文本量大 50%，引用
跳转读到的上下文更稀释；372 vs 450 只省 17% 存储；还超出 bge-m3 对检索单元
的建议窗口。而它换来的是 1 题噪声级收益。CRUD-RAG 论文测了 64/128/256/512
四档，结论也是"问答类任务块不是越大越好"。**用确定性指标做决策，召回差异
只做参考。**

**Q：你们这个测评集有多大说服力？300 篇 CMRC 够吗？**
A：分块是局部操作，参数排序主要取决于"单块内部怎么切"，300 篇已经产生
450 个子块、几十个真实切分边界。当然它测不到跨领域长文档（财报、法律），
所以路线图里有 DuReader 长文档扩语料——这也是我把"没测什么"写进报告的
原因：一个不敢写局限的评测不可信。

**Q：如果老板说"召回 97.5% 不够，我要 99%"，你怎么办？**
A：先看错在哪环。这次失败归因已经表明：6 个失败里 5 个是口语化查询
（改写/向量腿的问题，不是切块），1 个是切断边界（噪声级）。提升路径是
打开稠密腿+重排做分层评测，而不是动切块参数——数据显示切块参数在当前
语料上已经到顶了。

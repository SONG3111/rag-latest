# 端到端回答质量测评（试点）· 通俗版

> 目标读者：不需要懂 RAG 的同事/朋友。先说结论：**这一测只跑了个开头
> （16/86 题），因为 AI 服务的免费额度用完了**——但跑出来的开头已经
> 很有信息量，而且整套考试系统建好了，额度恢复后一条命令就能考完。

## 一、这一测和前两轮有什么不同

前两轮（CRUD-RAG、CMTEB）考的都是"资料找得准不准"。这一轮考最终
体验：**把资料真的递给 AI 写答案，答案写得好不好？**

考法：

1. 同一批 86 道新闻题，用两种检索配置各跑一遍——
   - 只按关键词找资料；
   - 完整配置（关键词 + 语义 + 重排精读，也就是生产系统的完整形态）；
2. 把找到的资料交给**真实的 AI 模型**（qwen3.8-flash，生产同款）写答案；
3. 拿 AI 写的答案和标准答案对比打分（ROUGE-L，字面重合度 0~1，
   也是 CRUD-RAG 官方用的判分方式）。

## 二、试点跑出了什么（16 题）

一个出乎意料但想通了很有价值的现象：**两种配置的得分一模一样**
（比如都是 0.972、都是 0.521）。

为什么？因为在这个题库上，检索早就"满分"了（前两轮证明的）——两种
配置找到的**都是同样那几篇资料**。资料一样，AI 写出的答案自然一样，
分数当然一样。

> 这说明一个重要的道理：**资料找得准之后，继续优化"找资料"对答案
> 质量就没有帮助了。** 想让答案更好，该优化的是"怎么用资料"——喂给
> AI 几段、怎么组织、怎么提问。这为下一阶段的工作指了方向。

这个结论和 CRUD-RAG 官方论文的发现（检索增强对单文档问答的答案提升
很小）互相印证。

## 三、为什么没跑完（如实说）

第 17 题开始，AI 服务的接口开始返回"**免费额度已用尽**"（这个账号开着
"仅免费模式"，充值或关闭该模式才能继续；重排的云端接口也是同一堵墙，
所以前面的重排测评全部用的本地模型）。

脚本对这种故障做了正确处理：把失败的调用记录下来、不计入统计，所以
恢复后重跑不会被这次的中途故障污染。

## 四、现在能做什么

- **已交付**：完整的考试系统（`scripts/eval_crud_answers.py`）——
  两条检索配置、生产同款上下文组装与提示词、ROUGE-L 判分、逐题明细
  与错误记录，全部自动化；
- **恢复后一条命令考完**：
  ```bash
  python scripts/eval_crud_answers.py --out docs/rag-test-report/9-18/data/crud-answers-eval.json
  ```

## 五、一句话总结

**试点证实：在资料检索已经满分的题库上，"找得更准"传导不到"答得
更好"——答案质量的下一战场在生成端。** 考试系统已就绪，云端额度恢复
即可出全量成绩单。

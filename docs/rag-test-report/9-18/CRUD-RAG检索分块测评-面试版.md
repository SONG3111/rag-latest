## 2. 测评集构成（重点）

### 2.1 为什么选 CRUD-RAG

[CRUD-RAG](https://github.com/IAAR-Shanghai/CRUD_RAG)（IAAR-Shanghai，
arXiv:2401.17043，Apache-2.0）是中文 RAG 评测被引最多的公开基准之一：

- **任务设计贴真实 RAG**：Create/Read/Update/Delete 四类任务，其中 Read
  是"给文档库、 answer 问题"的标准 RAG 问答，语料是 **2023 年后的中文新闻**——
  恰好是我们系统最典型的"无结构长文"形态，和前两轮 CMRC 短段落互补；
- **规模够大、标注干净**：官方 Read 任务 9,580 道 QA、86,834 篇新闻，
  我们使用其预处理子集（下述）；
- **有官方对照结论**：论文做过 64/128/256/512 字四档分块、单/多文档 QA
  分类、检索器消融（Dense / Hybrid / Hybrid+Rerank），我们的数字可以直接
  和它的结论互相对照。

前两轮报告里我们明确写过"CRUD-RAG 语料不搬"（8 万文档 + GPT 裁判与离线
纪律冲突）。本轮用户授权真实模型调用，约束解除，于是把它搬进来——**三轮
报告的选型逻辑是连贯的：不是不测权威基准，是在等测量手段到位。**

### 2.2 本轮用的子集（已入库 `tests/datasets/crud_rag/`）

| 项 | 数值 | 说明 |
| --- | --- | --- |
| 文档 | 3,000 篇新闻 txt | 中位 707 字符、p90 925、最大 151,068（保留离群长文，考验切块器） |
| 标注问题 | 86 道 | 每道绑定**唯一**回答它的文档（`relevant_chunks` 指向 `qa_XXXX_news1.txt#0`），附参考答案 |
| 预处理口径 | `prepare_stats.json` | 官方 qa 采样 100 → 剔除改写歧义 14 → 留 86；干扰文档 3,000 篇 |

**为什么敢用 86 题子集**：CRUD-RAG 官方检索指标是 MRR，它的单文档子集
天然"一篇文档只对应一道题"；3000 : 86 的干扰比已经能拉开检索器差距
（官方论文在完整库上也只报均值级差异）。86 题里 1 题的变化 = 1.2 个百分点，
报告里所有结论都标注了题目数。

### 2.3 标注格式与判分口径

- 每道题：`query`（用户问题）+ `answer`（参考答案，官方生成式摘要）+
  `relevant_chunks`（**文档级**标注）；
- 判分用**文件级 HitRate@k / MRR@k**：前 k 个检索结果里出现标注文档即命中。
  为什么不用答案串匹配：参考答案是改写过的陈述句（如官方答案"……灵感来源
  于祥云纹"，原文写的是"融入中国传统纹饰：祥云纹设计"），字符串匹配判的
  是措辞不是检索——官方检索口径也是 MRR/排名，不匹配答案串。

## 3. 测试方法（重点）

### 3.1 快速路径：与生产逐环节对齐的内存重放

3,000 个 txt 各包成单段落 docx（生产唯一支持的解析格式），然后用**生产
同款代码**切块（`chunk_word_groups` + `build_body_splitter`，bge-m3
tokenizer 计 token），子块用生产同款 bge-m3 权重嵌入，检索用生产同款
`BM25Index`（jieba+bigram）与 `reciprocal_rank_fusion`。

**可信度锚点——等价性校验**：用真实 `Retriever`（SQLite + Qdrant 全套）
在 12 文件工作区上跑 10 题，与快速路径逐位对拍：**0/10 不一致**。
这条校验沿袭第二轮的传统：测得的必须是线上跑的那个东西。

### 3.2 四种检索模式（对应管线开关组合）

| 模式 | 组成 | 对应生产行为 |
| --- | --- | --- |
| bm25 | 稀疏腿，top-20 → 指纹去重 | 关键词检索兜底 |
| dense | bge-m3 余弦，top-20 → 去重 | 向量腿 |
| hybrid | 双腿 RRF 融合（dense 1.0 / bm25 0.8，k=60）→ top-20 | 现行生产配置 |
| rerank | hybrid 候选 → bge-reranker-v2-m3 交叉编码器重排 | 现行生产完整链路 |

四种模式都跑每道题，**同题同库同嵌入，只有"开哪些环节"不同**——模式间
差异即环节贡献。

### 3.3 参数与成本

- 分块档位：128 / 256 / 512 / 1024 token（overlap 固定 64）；
- 嵌入总量：29.0k + 11.3k + 5.6k + 3.5k = **49.4k 子块向量**，本地 bge-m3
  CPU 推理约 4.5 小时（这就是前两轮"零模型调用"纪律下做不了这套测评的
  原因，也是本轮授权真实模型的意义）；
- 重排：86 题 × 20 候选 + 86 题 × 50 候选（候选数扫描），本地交叉编码器
  CPU 推理约 50 分钟；
- 另扫 RRF 融合权重 4 组（无模型成本）与重排候选数 {20, 50}。

### 3.4 附加 A/B：RAGFlow 式自动关键词（调研驱动的验证性实验）

调研结论里 RAGFlow 的"自动关键词"（对每块抽 TF-IDF 关键词拼进索引文本）
是社区常用的低成本检索增强。我们按其语义实现
（`jieba.analyse.extract_tags` 取块内 top-3/5 关键词，追加
`\n关键词：…`），在 512/64 生产档上做 BM25 腿 A/B——**这是"先测再上线"
纪律的执行，不是拍脑袋采纳。**

## 4. 核心数据

### 4.1 主表：四档分块 × 四种模式（86 题，文件级）

**hit@5 与 hit@10 在所有 16 个组合里全部 = 100%。** 差异全部发生在
top-1 / top-3 的排序精度上：

| 配置 | 子块数 | bm25 hit@1 | dense hit@1 | hybrid hit@1 | rerank hit@1 | hybrid MRR@10 |
| --- | --- | --- | --- | --- | --- | --- |
| 128 | 28,998 | 98.84% | 98.84% | 98.84% | — | 0.9922 |
| 256 | 11,263 | 98.84% | 98.84% | 98.84% | — | 0.9922 |
| **512（现行）** | **5,587** | **98.84%** | 97.67% | 98.84% | 98.84% | 0.9913 → **重排 0.9942** |
| 1024 | 3,549 | 100% | 98.84% | 98.84% | — | 0.9942 |

三个读数：

1. **基准饱和**：86 道单跳新闻题对混合检索太容易——每题答案文档含独特
   实体（品牌、活动名），BM25 一腿就能命中。hit@5 全线 100% 意味着**分块
   参数在这个基准的 top-5 口径上没有区分度**，区分度在 top-1 排序与成本；
2. **成本差 5 倍，收益 ≈ 0**：128 档子块数是 512 档的 5.2 倍（嵌入、存储、
   检索计算同步 ×5.2），top-1 却与 512 持平。CRUD-RAG 论文"小块利于单文档
   QA"的结论是在其完整 86k 库 + 生成端指标下得出的；在我们这个子集 +
   排序口径下，小块的红利被父块上下文抹平了——**父块架构本身就是对
   "小块精度"的另一种收割方式**；
3. **唯一失手题 crud-0080**（86 题中唯一的非 top-1，多约束长查询：日期 +
   五部门 + 通知名 + 领域四重过滤）：其标注文档排名随模式浮动
   bm25=4 / dense=2~4 / hybrid=2~4，**重排把它从 rank4 修到 rank2**，
   1024 档（整篇一块）对它最友好（bm25 直接 rank1）。一道题概括了三个
   设计选择的理由。

### 4.2 环节贡献（512/64 档）

| 环节 | 证据 | 结论 |
| --- | --- | --- |
| BM25 稀疏腿 | hit@1 98.84%，MRR 0.9913 | 新闻实体词场景的定海神针 |
| dense 向量腿 | hit@1 97.67%（2 题掉到 rank2/4） | 单腿略弱于 bm25（口语化改写少的基准上正常） |
| hybrid 融合 | hit@1 回到 98.84%，top-3 全命中 | 融合修复单腿抖动，RRF 四组权重**零差异**（1.0/0.8 保留） |
| rerank 重排 | MRR 0.9913 → 0.9942，唯一失手题 rank4→2 | 排序精度的最后一档，且只在模糊案例上出手 |

### 4.3 候选数与关键词 A/B

- **重排候选 20 → 50**：MRR 完全一致（0.9942）。候选翻 2.5 倍换不来第 3 个
  9——top-20 融合池在这个基准上已装下全部可能，**候选数维持 20 不改**
  （CPU 本地重排延迟直接省 2.5 倍）；
- **RAGFlow 式关键词附注（kw3 / kw5）**：hit@1、hit@5、MRR 与 baseline
  **逐位相同**。原因是结构性的：关键词从块内文本用 TF-IDF 抽出，而这些
  词本来就在块里、已在 BM25 索引里——附注只对"块本身缺上下文词"的短块
  有效，512 档新闻块是自描述的。**负结果，不上线**，但测量过程留档
  （[data/keyword-ab.json](./data/keyword-ab.json)）。

### 4.4 与 CRUD-RAG 官方结论的对照

| 官方论文结论（Read 任务） | 本轮测量 | 一致性 |
| --- | --- | --- |
| 单文档 QA 偏好小块（128 字符最优） | top-5 口径下 128~1024 无差异；top-1 上小块无优势且成本 ×5 | **部分相反**——归因于我们粒度是"检索排序"，官方偏生成端；且父子架构已收割小块红利 |
| Hybrid+Rerank 对单文档 QA 提升很小（bleu +0.87） | 重排仅把 1/86 题的 rank4→2 | **一致**：单跳新闻问答重排收益天然小 |
| 检索指标 MRR | 同用 MRR@10 | 同口径 |

**敢报"部分相反"是这轮最有价值的地方**：基准结论不是圣经，任务形态
（生成端 vs 排序端）决定什么参数最优。

## 5. 决策与落地

| 项 | 决定 | 依据 |
| --- | --- | --- |
| 分块 512/64 | **保留** | 权威基准 top-5 全饱和；更小块 5 倍成本零收益；更大块只在单道多约束题上占优 |
| RRF 权重 1.0/0.8 | **保留** | 四组权重零差异，动它没有意义 |
| 重排候选数 20 | **保留** | 50 无增益，本地 CPU 重排延迟省 2.5 倍 |
| RAGFlow 关键词附注 | **不上线** | A/B 零差异（负结果留档） |
| 测评资产 | 沉淀脚本 | `scripts/eval_crud_rag.py`（含等价性校验）、数据集与标注入库 `tests/datasets/` |

## 6. 追问预演

**Q：86 题是不是太少？**
A：太少的是"每格 1 题"的差异判断，不是题量本身——所以我们把所有结论
挂在"题目数 + 结构性成本"双证据上：凡是 ±1 题的差异一律标注为噪声级，
决策改由成本指标驱动（128 档 ×5.2 子块、候选数 ×2.5 延迟）。题量要扩
该扩的是**多跳/多文档题**（官方 Read 任务还有 3,192 道双文档 + 3,189 道
三文档 QA），那是下一轮。

**Q：基准饱和了，这轮不就白测了？**
A：恰恰相反——"现在的架构在公认基准上已到顶"本身就是要花钱才能知道的
结论。它把优化火力从"调参"赶到了"换更难的题"（多跳）和"答得更对"
（端到端 ROUGE-L，见姊妹篇）。同时它证伪了两个我们差点跟风的优化
（小块化、关键词附注），避免的是生产事故级的浪费。

**Q：重排只修了半道题， why keep it？**
A：看它修的是**哪半道**。crud-0080 是全库最难的多约束题，四档分块 × 两条
检索腿谁都拿不住它，只有交叉编码器把它从 rank4 拉到 rank2——这正是
"recycle 精读"该干的活。在业务语料上（前一轮）重排还承担相关性门控
（拒答），CRUD 子集没有负样本所以测不到那部分。

**Q：等价性校验只对拍了 10 题，凭什么信 5 万向量的快速路径？**
A：因为对拍的是**代码路径**不是抽样统计：快速路径与生产共用 `BM25Index`、
`reciprocal_rank_fusion`、`content_fingerprint`、切块器、reranker 封装，
唯一差异是向量读取（numpy vs Qdrant）——10 题对拍 0 不一致覆盖的就是
这个差异面。这与第二轮"BodySplitter 预算契约"是同一方法论：**先证明
测的就是线上跑的，再谈数字。**

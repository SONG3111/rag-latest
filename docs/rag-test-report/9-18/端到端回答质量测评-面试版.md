## 1. 为什么需要这一测（问题定义）

前两篇分别证明了"找得到"（CRUD-RAG，hit@5 全饱和）与"排得准"
（CMTEB，重排三项精度最高）。但两者都是**检索层指标**——它们回答不了：

> 排序从 rank4 修到 rank2，用户看到的**答案**变好了吗？

检索指标与答案质量之间的传导不是必然的：上下文组装、模型阅读、答案
措辞都会稀释或放大检索端的差异。这是分层评测的最后一层，也是 CRUD-RAG
官方评估真正的主战场（其生成端指标：BLEU / ROUGE-L / bertScore +
RAGQuestEval）。

## 2. 测评集与方法

### 2.1 测评集

与 [CRUD-RAG检索分块测评](./CRUD-RAG检索分块测评-面试版.md) 完全同源：
3,000 篇新闻 + 86 道标注题（`tests/datasets/crud_rag/`），每题附官方
参考答案（约 55 字符的陈述句）。

### 2.2 链路与消融

每道题跑两条配置，其余全部固定：

| 配置 | 检索 | 目的 |
| --- | --- | --- |
| bm25 | BM25 top-5 父块上下文 | 基线：没有向量与重排时答案什么水平 |
| rerank | 混合 RRF → bge-reranker 重排 top-5 父块 | 完整生产链路的答案水平 |

- **上下文组装**：生产同款 `format_context` 语义（`[资料N] 文件 · 位置`
  + 父块全文）；
- **生成**：生产同款 qwen3.8-flash（DashScope，temperature=0），提示词
  要求"只根据资料、一句简短陈述句、没有就说没有"；
- **判分**：ROUGE-L F1（字符级 LCS 的 P/R/F1）对照官方参考答案——与
  CRUD-RAG 官方生成指标同口径。参考答案是改写过的摘要，所以 ROUGE-L
  是**相对信号**（用于模式对比），不是绝对质量分。

### 2.3 成本与并发

86 题 × 2 配置 = 172 次真实生成调用（4 并发，本地重排加锁串行）。
整轮预估 25 分钟、约 24 万输入 token。

## 3. 试点数据（16/86 题，配额耗尽前）

| 现象 | 数据 |
| --- | --- |
| 两模式 ROUGE-L 逐位相同 | 16 题中 13 题 bm25 与 rerank 分数完全一致（如 0.972/0.972、0.521/0.521） |
| 原因 | 检索层在 CRUD 语料已饱和：两模式 top-5 命中的**是同一批文档**，上下文相同 → 生成相同 → 分数相同 |
| 绝对水平 | ROUGE-L 0.52~0.97，跨度大——参考答案是摘要式改写，字面重叠天然波动 |

**能下的结论（试点级，非全量）**：在检索已饱和的基准上，重排带来的
排序精度提升（CRUD 轮：rank4→2）**传导不到答案层**——因为 top-5 的
"内容集合"没变，变的只是顺序，而 top-5 全进上下文时顺序不影响信息量。
这与 CRUD-RAG 官方论文"Hybrid+Rerank 对单文档 QA 生成端提升很小
（BLEU +0.87）"互相印证。

**它反过来指明重排的真实价值位置**：不在"top-5 全保留"的宽松场景，
而在 top_n 收紧（只取 1~3 段喂模型，省 token）或检索不饱和的真实
工作区——排序决定**谁被截掉**。

## 4. 阻塞点（如实报告）

- **现象**：第 17 题起生成调用全部 403 `Free quota exhausted`；同账号
  qwen-turbo / qwen-flash / qwen-plus 全部 403（账号级"仅免费模式"，
  非单模型配额）；此前 gte-rerank 云端同样耗尽（这也是 CMTEB/CRUD 重排
  全部走本地 bge-reranker 的原因）；
- **影响**：86 题全量无法完成；`rerank=0.000` 的行是错误路径记录的
  空答案（脚本对每次调用记录 `error` 字段，污染可被识别与剔除）；
- **解除条件**：管理台关闭"仅免费模式"或充值；换任一可用 OpenAI 兼容
  端点亦可（脚本经 `LLM_BASE_URL`/`LLM_MODEL` 配置，无代码改动）。

## 5. 复跑路径

```bash
# 配额恢复后一条命令（嵌入与切块全部命中缓存，仅生成调用）
python scripts/eval_crud_answers.py --out docs/rag-test-report/9-18/data/crud-answers-eval.json
# 冒烟（8 题，1 分钟级）
python scripts/eval_crud_answers.py --limit-queries 8
```

产出：双模式 ROUGE-L 均值/中位、胜负计数、逐题答案与耗时明细（JSON）。

## 6. 追问预演

**Q：16 题的试点就敢写结论？**
A：试点结论只下到"信号"级，且与官方论文独立互证；报告通篇标注
"试点级，非全量"。真正要防的是反方向的错误——**拿全量预算去跑一个
检索已饱和、注定零方差的实验**。试点正是为了在花完配额之前发现这一点。

**Q：那这轮端到端的价值是什么？**
A：三件事：① 判分协议（ROUGE-L vs 官方参考答案）与 CRUD-RAG 官方口径
对齐并沉淀成脚本；② 用真实数据证实"检索饱和 → 答案层零传导"这条
传导规律，给后续优化定了位——**检索端参数已不是杠杆，生成端（上下文
组装、提示词、top_n 收紧）才是**；③ 摸清了配额运行时的熔断行为，
脚本对 403 的处理（记录、剔除、不污染统计）是跑过真实故障的。

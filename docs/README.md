# 项目详情文档

这套文档写给三类读者：**想快速了解项目的人**、**想看设计取舍的人**、**准备把它落地的人**。

主 README（[`../README.md`](../README.md)）讲的是"怎么装、怎么跑、有哪些坑"；这里讲的是
**为什么这么设计、系统怎么运转、还能怎么改**。

## 30 秒速览

| 维度 | 内容 |
|---|---|
| 它是什么 | 本地运行的文档工作台：上传 Excel / Word，用自然语言提问或直接改文档 |
| 交互形态 | Vue 三栏界面（工作区文件 / 对话 / 引用与待确认），SSE 流式 |
| 编排 | LangGraph 单 Agent + 工具循环，迭代上限 12 |
| 工具 | 独立 MCP Server（stdio 子进程），13 个 Excel / Word 工具，7 个写入类需审批 |
| 检索 | 查询改写 → 向量 + BM25 双路召回 → 去重 → RRF(k=60) → 交叉编码器重排 → 相关性阈值 |
| 模型 | LLM 走云端（百炼/OpenAI 兼容），Embedding 与 Reranker 走**本地权重** |
| 存储 | SQLite（元数据与审计）+ Qdrant local（每工作区一个 collection）+ 磁盘目录（沙箱） |
| 安全 | 路径沙箱、写前备份、审批闭环、可一键还原 |
| 规模 | 后端 79 项 + MCP 48 项测试，检索评测集 36 题（含 8 条拒答负样本） |

## 一图看懂数据流

```
用户
 │  ① 上传文件                   ② 提问 / 要求改文件
 ▼                                    ▼
┌───────────┐                  ┌──────────────────────────┐
│ Vue 前端  │ ── POST 上传 ──▶ │ FastAPI                  │
│ 三栏界面  │ ◀── SSE 流 ───── │ REST + SSE 路由          │
└───────────┘                  └───────┬──────────────────┘
                                       │
                    ┌──────────────────┴───────────────────┐
                    ▼                                      ▼
        ┌───────────────────────┐              ┌────────────────────────┐
        │ 索引链路               │              │ LangGraph Agent        │
        │ 解析→父子分块→嵌入      │              │  决策 → 调工具 → 再决策 │
        └──────────┬────────────┘              └────┬───────────────┬───┘
                   ▼                                ▼               ▼
        ┌───────────────────────┐        ┌────────────────┐ ┌──────────────────┐
        │ SQLite: chunks        │        │ 检索工具        │ │ MCP 子进程        │
        │ Qdrant: 向量           │◀───────│ 改写/双路/重排  │ │ Excel / Word 读写 │
        └───────────────────────┘        └────────────────┘ └────────┬─────────┘
                                                                     ▼
                                                          ┌────────────────────┐
                                                          │ 工作区目录（沙箱）  │
                                                          │ + 写入前自动备份    │
                                                          └────────────────────┘
```

关键点：**检索与文件读写是两条完全独立的能力**，由 Agent 在每一轮自己决定调用哪条；
而"写入"永远不直接落盘，先变成一条可审批、可还原的提案。

## 核心概念表

| 概念 | 一句话解释 | 代码位置 |
|---|---|---|
| 工作区 Workspace | 一个独立的知识库 + 一个磁盘目录，彼此不共享 | `backend/app/models.py` |
| 父子分块 | 子块用于命中与引用（一行/一段），父块用于给模型上下文（行组/章节） | `backend/app/retrieval/chunking.py` |
| MCP 工具 | 通过 MCP 协议暴露的文档能力，带 `readOnlyHint` / `destructiveHint` 注解 | `mcp-office-server/src/mcp_office_server/server.py` |
| 提案 Proposal | 一次写入意图。落库但**不执行**，等用户确认 | `backend/app/services/operations.py` |
| Diff | 提案的逐项变更（单元格、原值、新值），用于界面展示与审计 | 同上 |
| 相关性阈值 | 重排分数下限（默认 0.02），低于它直接丢弃，让"不知道"成为合法答案 | `backend/app/retrieval/pipeline.py` |
| 时效性检测 | 文件在上一条消息之后变过时，本轮注入提示并要求重新读取 | `backend/app/api/routes.py` |
| 兜底 Nudge | 模型没读文件就给结论、或干脆没输出正文时，系统把它打回一次 | `backend/app/agent/graph.py` |

## 这套文档里的数字从哪来

凡是标注"实测"的数字，都能用仓库里的脚本复现：

| 数字 | 复现命令 |
|---|---|
| 检索 Recall@5 / MRR / 拒答准确率 | `python scripts/eval_retrieval.py --dense --rewrite` |
| 阈值标定曲线 | `python scripts/eval_retrieval.py --dense --sweep` |
| 一次对话的工具调用链与耗时 | `python scripts/ask.py "<问题>"` |
| 原始 SSE 事件序列 | `python scripts/dump_sse.py "<问题>"` |
| 审批闭环是否真的不落盘 | `python scripts/check_proposal_flow.py` |
| 前端 SSE 解析（含 CRLF） | `cd frontend && npm run check:sse && npm run check:sse:live` |

> 环境差异会改变延迟类数字（CPU 型号、是否首次加载本地权重、模型供应商的排队情况）。
> 质量类数字（Recall/MRR/拒答）只依赖语料与模型，复现性更好。
